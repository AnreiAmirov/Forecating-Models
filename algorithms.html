How to solve a problem at an interview

Interviewers rarely judge only whether you reach the answer. They watch how you think: whether you clarify the task, start from something that works, and improve it deliberately. Silence for ten minutes followed by perfect code scores worse than reasoning aloud and arriving at a good solution. Six steps make that process visible.

  1. ClarifyRestate the task in your own words. Ask about the edges: can the array be empty? Are there negatives or duplicates? Is the input sorted? Each answer can change the solution.
  2. Work an example by handTake a small input and solve it on paper. This is where you notice the pattern — and catch a misunderstanding before writing a line of code.
  3. Say the brute forceDescribe the obvious solution and its complexity, even if it is slow. It proves you understand the task and gives a baseline to improve on.
  4. Find the bottleneckAsk what work is repeated. Usually it is a nested loop re-scanning data you have already seen — the classic place where a dictionary, two pointers or a running sum helps.
  5. Write the codeClear names, small steps, comments where intent is not obvious. Readable code is part of the grade, not decoration.
  6. Test it yourselfWalk through your example line by line, then the edges: empty input, one element, all equal values. Finding your own bug is a plus; the interviewer finding it is a minus.
The most common mistake is jumping straight to code. Two minutes spent clarifying and working an example save twenty minutes of rewriting a solution to the wrong problem.
The logic behind the solution

Knowing the code by heart does not help when the task is worded slightly differently. What transfers is the reasoning. Three topics come up at almost every analyst interview — strings and counting, sorting, and two pointers — so here they are taken apart slowly, with the questions you should be asking yourself at each step.

Four questions that start almost any solution
  1. Does order matter? "Count the letters" and "count letters in a row" are different tasks.
  2. What must I remember while walking through the data? A counter, the previous element, the best value so far, what I have already seen.
  3. When does what I remember change? This moment — "the run broke", "the sum got too big" — is the heart of the algorithm.
  4. What is left over at the end? Many bugs live here: the last group is never written because the loop ended first.

1 · Strings and counting characters

A string is a sequence of characters, just like a list. You can loop over it, take s[i] by position and look back at the previous character with s[i - 1]. One difference matters: strings cannot be changed in place. So the result is collected in a list and glued together once at the end with "".join(parts).

The fork that decides everything: "in total" or "in a row"?

The task "count the characters and print 2a2b3c" hides two different questions. For aabbccc they give the same answer — which is exactly why the difference goes unnoticed. Take abab: counting in total gives 2a2b, counting runs in a row gives 1a1b1a1b. Ask the interviewer which one they mean — that question alone shows you think before you code.

# compress() and count_chars() are defined further down this page

How to reason about "in a row"
  1. Walk through the string and compare every character with the previous one.
  2. Keep one counter for the current run. Same character — the run continues, add one.
  3. Different character — the run has broken: write down "count + character" and reset the counter to 1.
  4. After the loop, write down the last run. Nothing inside the loop ever triggers it — this is the most common bug.

def compress(s):
    """'aabbccc' -> '2a2b3c': count each run of identical neighbours."""
    if not s:
        return ""
    parts = []
    count = 1
    for i in range(1, len(s)):
        if s[i] == s[i - 1]:          # same as the previous char: the run goes on
            count += 1
        else:                         # the run broke: write it down, start a new one
            parts.append(f"{count}{s[i - 1]}")
            count = 1
    parts.append(f"{count}{s[-1]}")   # the loop never writes the LAST run
    return "".join(parts)
And "in total": a dictionary as a tally

Here order does not matter, so we do not look at neighbours at all. A dictionary stores "character → how many times". The line counts.get(ch, 0) + 1 means "take the current count, or 0 if this is the first time, and add one". Counter does the same in one word, but interviewers often ask for the version without imports — know both.

def count_chars(s):
    """'abcab' -> '2a2b1c': total count of every char, in alphabetical order."""
    counts = {}
    for ch in s:
        counts[ch] = counts.get(ch, 0) + 1
    return "".join(f"{counts[ch]}{ch}" for ch in sorted(counts))
Where people slip: forgetting the last run; crashing on an empty string; and a run of ten or more — 12a — which breaks any decoder that reads only one digit. Test all three before saying "done".

2 · Sorting: when it helps and how to control it

Sorting is rarely the answer by itself — it is the step that makes the answer easy. After sorting, similar things stand next to each other: duplicates sit in a row, close values become neighbours, and the smallest and largest are at the two ends. That is what makes two pointers and "compare with the neighbour" work. The price is O(n log n), so it pays off when it removes an O(n²) search.

sorted() or .sort() — and the classic bug

sorted(x) returns a new sorted list and leaves x untouched. x.sort() sorts the list itself and returns None. So x = x.sort() silently replaces your data with None — one of the most frequent mistakes in live coding.

data = [3, 1, 2]
result = sorted(data)
print(result, data)    # a new list; data is unchanged

result = data.sort()
print(result, data)    # None — and data itself is now sorted
# output when run:[1, 2, 3] [3, 1, 2] None [1, 2, 3]
Sorting by several rules at once: the key

The key argument is a function that turns each element into "what to compare". If it returns a tuple, Python compares the first values, and only on a tie looks at the second. A minus sign flips a number into descending order. So key=lambda kv: (-kv[1], kv[0]) reads as: "most frequent first; on a tie — alphabetically".

from collections import Counter

counts = Counter("mississippi")
ranked = sorted(counts.items(), key=lambda kv: (-kv[1], kv[0]))
print(ranked)
print("".join(f"{n}{ch}" for ch, n in ranked))

If you are asked to write a sort yourself

Insertion sort is the easiest to explain, because it is how people sort cards in their hand. The left part is always sorted. Take the next card and slide it left past every bigger card until it fits. It is O(n²), so in real work you use sorted() — Python's built-in algorithm is O(n log n). But being able to state the rule "the left part stays sorted" is exactly what the interviewer is checking.

def insertion_sort(nums):
    nums = nums[:]
    for i in range(1, len(nums)):
        current = nums[i]
        j = i - 1
        while j >= 0 and nums[j] > current:   # shift bigger values one step right
            nums[j + 1] = nums[j]
            j -= 1
        nums[j + 1] = current                 # drop current into the gap
    return nums

3 · Two pointers: three shapes of one idea

Two indexes move through the data by a rule, instead of a loop inside a loop. Every step moves at least one pointer, so the whole walk takes at most n steps — O(n). Everything depends on the rule: which pointer moves, and why that move can never skip the right answer. If you can say that sentence out loud, you understand the solution.

Shape A · towards each other

One pointer at each end, moving inwards. Works on sorted data and on symmetric questions (palindromes, reversing). Take a sorted list and a target sum. If the sum of the two ends is too small, the left number cannot be part of any answer — even paired with the largest remaining number it falls short. So we drop it and move left. If the sum is too big, the same logic drops the right number.

def two_sum_sorted(nums, target):
    """Sorted list: positions of two numbers that add up to target (opposite pointers)."""
    left, right = 0, len(nums) - 1
    while left < right:
        total = nums[left] + nums[right]
        if total == target:
            return [left, right]
        if total < target:
            left += 1                 # need a bigger sum: only moving left can give one
        else:
            right -= 1                # need a smaller sum: only moving right can give one
    return []

Shape B · same direction, fast and slow

Both pointers start on the left. F (fast) reads every element. S (slow) marks where the "good" part of the array ends. When fast finds something worth keeping, it is copied to the slow position and slow moves on. This is how you clean an array in place without a second list: removing duplicates, moving zeroes to the end, compressing.

def remove_duplicates(nums):
    """Sorted list: keep unique values at the front, return how many."""
    if not nums:
        return 0

    for fast in range(1, len(nums)):  # fast scans everything
        if nums[fast] != nums[slow]:
            slow += 1
            nums[slow] = nums[fast]
    return slow + 1

Shape C · one pointer on each of two lists

When two sorted lists have to be combined or compared, give each its own pointer. At every step compare the two current elements, use the right one, and move only that pointer. Merging sorted lists, checking whether one string is a subsequence of another, and finding common elements all follow this shape.

def is_subsequence(s, t):
    i = 0                             # how much of s is already matched
    for ch in t:
        if i < len(s) and s[i] == ch:
            i += 1
    return i == len(s)

Where people slip: while left < right versus <= (decide whether the middle element can pair with itself); forgetting to move a pointer in one branch — an endless loop; and using shape A on data that is not sorted, where the "drop it" logic is no longer true.
The sentence to say at the interview: before writing code, describe your rule in one line — "I compare with the previous character and write the run when it breaks", "I move the pointer with the smaller value". Interviewers grade this sentence as much as the code.
Complexity: what Big-O actually means

Big-O answers one question: when the input grows, how fast does the work grow? It does not measure seconds — those depend on the computer. It describes the shape of growth. O(n) means "twice the data, twice the work". O(n²) means "twice the data, four times the work".

The chart shows why this matters more than any micro-optimisation. On small inputs every approach is fast. As the data grows, O(n²) leaves the others behind — and that is the curve your interviewer wants you to avoid.

A real measurement, not a promise

Both functions below solve Two Sum. I timed them on arrays of growing length, on the worst case where no answer exists and every element must be checked. The numbers are measured, not modelled.

def two_sum_brute(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):   # every pair
            if nums[i] + nums[j] == target:
                return [i, j]
    return []

def two_sum(nums, target):
    seen = {}                          # value -> index
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:
            return [seen[need], i]
        seen[x] = i
    return []
Look at the step from 2,000 to 4,000 elements: the input doubled, the nested loops became roughly four times slower, and the dictionary only twice as slow. That is O(n²) against O(n) — visible in real milliseconds.
Memory counts too. The fast solution stores up to n values in a dictionary — O(n) extra memory. That is the usual trade: spend memory to save time. Interviewers often ask "can you do it with O(1) memory?" — be ready to say what it would cost.

1Run-length encoding: aabbccc → 2a2b3c
Strings and charactersEasyInterview classic

Replace every run of identical neighbouring characters with "count + character".

"aabbccc" → "2a2b3c" "abab" → "1a1b1a1b" "" → ""
  1. Order matters — this is "in a row", not "in total". So compare each character with the previous one.
  2. Keep a counter. Same as previous → +1. Different → write the finished run and reset the counter to 1.
  3. After the loop the last run is still unwritten — write it. And handle the empty string first.
def compress(s):

            parts.append(f"{count}{s[i - 1]}")
            count = 1
    parts.append(f"{count}{s[-1]}")   # the loop never writes the LAST run
    return "".join(parts)
Why it works
One pass, O(n). The only non-obvious line is the one after the loop — exactly the one interviewers watch for.

2The reverse: 2a2b3c → aabbccc
Strings and charactersEasyInterview classic

Decode a string of "count + character" back to the original. Counts can have more than one digit.

"2a2b3c" → "aabbccc" "12z" → "zzzzzzzzzzzz"
  1. A number can be "12", so you cannot read one digit and move on. Collect digits until a letter appears.
  2. When the letter comes, repeat it as many times as the collected number says, then clear the number.
def decompress(code):
    """'2a2b3c' -> 'aabbccc'. Counts may have several digits: '12a'."""
    out = []
    digits = ""
    for ch in code:
        if ch.isdigit():
            digits += ch              # keep collecting the number
        else:
            out.append(ch * int(digits))
            digits = ""
    return "".join(out)
Why it works
A good self-check: decoding your own encoder must give back the original. The cross-check of this page does exactly that on random strings.

3Count every character in total: abcab → 2a2b1c
Strings and charactersEasyInterview classic

Count how many times each character appears anywhere in the string, and print them in alphabetical order.

"abcab" → "2a2b1c" "banana" → "3a1b2n"
  1. Order does not matter — this is "in total". Neighbours are irrelevant, a dictionary "character → count" is enough.
  2. Fill it in one pass with counts.get(ch, 0) + 1, then walk the keys in sorted order to build the answer.
def count_chars(s):

    counts = {}
    for ch in s:

    return "".join(f"{counts[ch]}{ch}" for ch in sorted(counts))
Why it works
Compare with the previous problem on "abab": same output format, different meaning. Clarifying which one is wanted is half of the answer.

4First unique character
Strings and charactersEasy#387 Open on LeetCode ↗

Return the position of the first character that appears exactly once, or −1 if there is none.

"leetcode" → 0 "loveleetcode" → 2 "aabb" → -1
  1. You cannot know a character is unique until you have seen the whole string. So one pass is not enough.
  2. Pass 1: count everything. Pass 2: walk again in the original order and return the first character with count 1.
def first_uniq_char(s):
    counts = Counter(s)               # pass 1: how many of each
    for i, ch in enumerate(s):        # pass 2: the first one seen exactly once
        if counts[ch] == 1:
            return i
    return -1
Why it works
Two passes is still O(n). "Count first, then decide" is a pattern that recurs constantly.

5Valid anagram
Strings and charactersEasy#242 Open on LeetCode ↗

Decide whether two strings consist of exactly the same letters, the same number of times.

("anagram", "nagaram") → True ("rat", "car") → False
  1. Different lengths — answer False immediately. A cheap check first.
  2. Then compare the letter counts. Two equal tallies mean an anagram. Sorting both and comparing also works, at O(n log n).
def is_anagram(s, t):
    if len(s) != len(t):
        return False
    return Counter(s) == Counter(t)
Why it works
Counting is O(n) and sorting O(n log n) — be ready to name both and say which is faster.

7Longest common prefix
Strings and charactersEasy#14 Open on LeetCode ↗

Find the longest beginning shared by all the words.

["flower", "flow", "flight"] → "fl" ["dog", "car"] → ""
  1. The answer can never be longer than the first word, so start with the whole first word as a candidate.
  2. For each next word, shorten the candidate from the end until the word starts with it. An empty prefix always fits, so the loop always stops.
def longest_common_prefix(words):
    if not words:
        return ""
    prefix = words[0]
    for word in words[1:]:
        while not word.startswith(prefix):
            prefix = prefix[:-1]      # shorten until it fits ("" always fits)
    return prefix
Why it works
The candidate only ever shrinks — a common trick: start from the most optimistic answer and narrow it down.

8Reverse a string in place
Two pointersEasy#344 Open on LeetCode ↗

Reverse a list of characters without creating a new list.

["h","e","l","l","o"] → ["o","l","l","e","h"]
  1. Shape A: one pointer at each end. Swap the two characters, then move both inwards.
  2. Stop when the pointers meet — after that you would swap everything back.
def reverse_string(chars):
    left, right = 0, len(chars) - 1
    while left < right:
        chars[left], chars[right] = chars[right], chars[left]
        left += 1
        right -= 1
    return chars
Why it works
n/2 swaps, O(1) extra memory. On LeetCode the function returns nothing; here it returns the list so you can see the result.
Tests to check yourself

10Move zeroes to the end
Two pointersEasy#283 Open on LeetCode ↗

Move every zero to the end of the list, keeping the order of the other numbers, in place.

[0, 1, 0, 3, 12] → [1, 3, 12, 0, 0]
  1. Turn it around: instead of pushing zeroes back, pull non-zeroes forward.
  2. Slow points to where the next non-zero belongs. Every non-zero found by fast is swapped there, and slow moves on.
def move_zeroes(nums):
    slow = 0                          # where the next non-zero should go
    for fast in range(len(nums)):
        if nums[fast] != 0:
            nums[slow], nums[fast] = nums[fast], nums[slow]
            slow += 1
    return nums
Why it works
Reframing the task ("move the good ones forward") is often what turns an awkward problem into shape B.

11Merge two sorted arrays

The first list has room at its end for the second. Merge them into the first list so it stays sorted.

def merge_intervals(intervals):
    intervals = sorted(intervals, key=lambda iv: iv[0])
    merged = []
    for start, end in intervals:
        if merged and start <= merged[-1][1]:

        else:
            merged.append([start, end])
    return merged

9Climbing Stairs
Dynamic programmingEasy#70 Open on LeetCode ↗
The task

You climb a staircase of n steps, taking 1 or 2 steps at a time. In how many different ways can you reach the top?

n = 3 → 3 # 1+1+1, 1+2, 2+1
The obvious approach

Recursion: ways(n) = ways(n−1) + ways(n−2). Correct, but it recomputes the same values again and again — exponential time, about 1.6ⁿ calls.

The key insight
To stand on step k, your last move came from step k−1 or step k−2. So ways(k) = ways(k−1) + ways(k−2). Compute it from the bottom up and remember each answer once. That is the whole idea of dynamic programming: solve small subproblems, reuse them.
Step by step
#step khowways[k]
11base case1
22base case2
33ways[2] + ways[1] = 2 + 13
44ways[3] + ways[2] = 3 + 25
55ways[4] + ways[3] = 5 + 38
66ways[5] + ways[4] = 8 + 513
77ways[6] + ways[5] = 13 + 821 ✓

Each row is built from the two above it. Step 7 has 21 ways — reached in 7 steps instead of the dozens of repeated calls plain recursion would make.

The solution
def climb_stairs(n):
    if n <= 2:
        return n
    prev, curr = 1, 2
    for _ in range(3, n + 1):
        prev, curr = curr, prev + curr
    return curr
ComplexityO(n) time · O(1) memory
Where people slip
Wrong base cases. With 1 step there is 1 way, with 2 steps there are 2. Getting these wrong shifts every answer that follows.
Where this shows up in analytics
Dynamic programming is behind sequence alignment, optimal budget allocation across channels, and counting paths through a funnel — any problem where the best answer is built from smaller best answers.

3Valid Palindrome
Two pointersEasy#125 Open on LeetCode ↗

def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1
        if s[left].lower() != s[right].lower():

        left += 1
        right -= 1
    return True
Why it works
The pointers compare matching positions from both ends without building a cleaned copy, so memory stays O(1).

43Sum
Two pointersMedium#15 Open on LeetCode ↗

Find every unique triple of numbers that sums to zero. The same triple must not appear twice.

[-1, 0, 1, 2, -1, -4] → [[-1, -1, 2], [-1, 0, 1]]
Sort first. Fix one number, then look for the other two with two pointers on the rest of the array. Skip equal neighbours to avoid duplicates.
def three_sum(nums):
    nums = sorted(nums)
    res = []
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue                       # skip duplicate anchors
        left, right = i + 1, len(nums) - 1
        while left < right:
            s = nums[i] + nums[left] + nums[right]
            if s < 0:
                left += 1
            elif s > 0:
                right -= 1
            else:
                res.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1
    return res
Why it works
Sorting turns "find two numbers summing to −x" into the two-pointer problem: too small → move left up, too big → move right down. Overall O(n²), down from O(n³).

6Maximum Average Subarray I
Sliding windowEasy#643 Open on LeetCode ↗

Find the contiguous stretch of exactly k numbers with the highest average, and return that average.

Do not re-add k numbers for every window. When the window slides one step, add the new number and subtract the one that left.
def find_max_average(nums, k):
    window = sum(nums[:k])
    best = window
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]
        best = max(best, window)
    return best / k
Why it works
Each slide costs two operations instead of k, so the whole scan is O(n) — the same trick as a 7-day rolling average.

StackMedium#739 Open on LeetCode ↗

For each day, return how many days you must wait for a warmer temperature. If it never gets warmer, return 0 for that day.

[73, 74, 75, 71, 69, 72, 76, 73] → [1, 1, 4, 2, 1, 1, 0, 0]

def daily_temperatures(temps):
    answer = [0] * len(temps)
    stack = []                          # indices of days still waiting
    for i, t in enumerate(temps):

            j = stack.pop()

        stack.append(i)
    return answer

Design a stack that supports push, pop, top, and returning the current minimum — every operation in constant time.

Store, next to every value, what the minimum was at the moment it was pushed.
class MinStack:
    def __init__(self):
        self.items = []                 # pairs: (value, min so far)
    def push(self, x):
        current_min = min(x, self.items[-1][1]) if self.items else x
        self.items.append((x, current_min))
    def pop(self):
        self.items.pop()
    def top(self):
        return self.items[-1][0]
    def get_min(self):
        return self.items[-1][1]
Why it works
Each entry carries its own snapshot of the minimum, so popping automatically restores the previous minimum — no searching required.

A list of non-overlapping intervals is sorted by start. Insert a new interval, merging wherever needed, and keep the result sorted.

[[1,3], [6,9]] + [2,5] → [[1,5], [6,9]]

def insert_interval(intervals, new):
    res = []
    i, n = 0, len(intervals)
    while i < n and intervals[i][1] < new[0]:
        res.append(intervals[i]); i += 1
    start, end = new
    while i < n and intervals[i][0] <= end:
        start = min(start, intervals[i][0])
        end = max(end, intervals[i][1])
        i += 1
    res.append([start, end])
    res.extend(intervals[i:])
    return res
Why it works
Because the input is already sorted, a single pass is enough — no re-sorting, O(n).

def coin_change(coins, amount):
    INF = amount + 1
    dp = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] != INF else -1
Why it works
Greedy fails here — with coins [1, 3, 4] and amount 6 it picks 4+1+1, while 3+3 is better. Dynamic programming checks every option once and finds the true minimum.

How to practise so it sticks

Solving a hundred problems once teaches less than solving thirty properly. A few habits make the difference.

  • Learn the pattern, not the answer. After each problem, write one sentence: "this was a sliding window because…". That sentence is what you will recall at the interview.
  • Give yourself 25 minutes. If you are stuck after that, open the hint. Still stuck after 10 more — read the solution, then solve it again from scratch the next day.
  • Talk out loud. Practise explaining your reasoning as you go. At an interview, silent coding is the most common way to lose points you actually earned.
  • Revisit after a week. Spaced repetition beats volume. A problem you can still solve seven days later is a problem you have learnt.
  • Always state the complexity. Finish every solution by saying its time and memory cost. Interviewers expect it, and it forces you to check whether there is a faster way.
