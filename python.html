1 · Python fundamentals

Not a tour of the language — only what an analyst actually uses, and each idea explained by why it exists, not just how it is typed.

1.1 · Types: a promise about a value

A type tells you what you may do with a value. Numbers add up, strings glue together. Mix them up and "120" + "80" silently becomes "12080" instead of 200 — a bug that raises no error and simply puts a wrong number in your report.

None deserves special care: it means "there is no value", which is not zero. A user who never bought has revenue None; a user who bought and refunded everything has 0. Treating them the same shifts your average.

# A type is a promise about what you can do with a value
users   = 1200              # int   — whole number
conv    = 0.048             # float — fractional
metric  = "checkout_rate"   # str   — text
is_sig  = True              # bool  — yes/no
missing = None              # None  — there is NO value (not zero!)

print(type(users), type(conv))

# The classic trap: numbers that are secretly strings
a, b = "120", "80"
print(a + b)            # 12080  — glued, not added
print(int(a) + int(b))  # 200    — as intended

# None is not zero
never_bought = None
refunded_all = 0
print(never_bought is None, refunded_all == 0)
# output when run (verified):<class 'int'> <class 'float'> 12080 200 True True
1.2 · Structures: list, dict, set

The structure you choose decides both readability and speed. The rule: list when order matters, dict when you look values up by key, set when you need uniqueness or a fast "is it there?" check.

The speed gap is not academic. A list checks elements one by one; a set jumps straight to the answer through a hash. Inside a loop over a million rows that is the difference between seconds and hours.

# List — order matters, access by position
revenue = [120.5, 80.0, 340.2, 55.0]
print(revenue[0], revenue[-1], revenue[1:3])

# Dict — lookup by key
user_plan = {101: "pro", 102: "free", 103: "pro"}
print(user_plan[102])                 # free
print(user_plan.get(999, "unknown"))  # safe default, no error

# Set — uniqueness and fast membership tests
paid_users = {101, 103, 107}
print(107 in paid_users)

# Why the choice matters for speed
import time
big_list = list(range(1_000_000))
big_set  = set(big_list)

t0 = time.perf_counter(); 999_999 in big_list; t_list = time.perf_counter() - t0
t0 = time.perf_counter(); 999_999 in big_set;  t_set  = time.perf_counter() - t0
print(f"list: {t_list*1000:.2f} ms | set: {t_set*1000:.4f} ms")
# output when run (verified):120.5 55.0 [80.0, 340.2] free unknown True list: 6.52 ms | set: 0.0013 ms
Practical rule: if you test membership inside a loop, convert the list to a set first. One line, and a slow script stops being slow.
1.3 · Conditions: teaching code to decide

An if asks a yes/no question and runs a block only when the answer is yes. With elif and else you build a chain: Python checks the conditions top to bottom and runs the first branch that is true — then skips the rest. That is exactly how you segment users by revenue, or turn a p-value into a verdict.

Python also treats values as true or false on their own — "truthiness". Zero, an empty string, an empty list and None count as false; everything else counts as true. That is why if orders: reads naturally as "if there are any orders".

# if / elif / else: Python checks conditions top to bottom
# and runs the FIRST branch whose condition is True.
def segment(revenue):
    if revenue >= 1000:
        return "VIP"
    elif revenue >= 100:        # reached only if the line above was False
        return "regular"
    elif revenue > 0:
        return "small"
    else:
        return "inactive"

for r in [2500, 340, 15, 0]:
    print(r, "->", segment(r))

# Comparisons combine with and / or / not
is_paid, is_new = True, False
print(is_paid and not is_new)          # True

# "Truthiness": empty things count as False
for value in [0, "", [], None, 42, "hi", [1]]:
    print(repr(value), "->", bool(value))

# One-line if (the "ternary" form)
p_value = 0.03
print("significant" if p_value < 0.05 else "not significant")
# output when run (verified):2500 -> VIP 340 -> regular 15 -> small 0 -> inactive True 0 -> False '' -> False [] -> False None -> False 42 -> True 'hi' -> True [1] -> True significant
The rule that prevents bugs: in an elif chain put the narrowest condition first. If revenue >= 100 came before revenue >= 1000, a VIP with 2500 would match the first line and be labelled "regular" — the VIP branch would never run.
1.4 · Loops: doing something for every element

A for loop takes a collection and runs the same block once for each element. Three helpers make it far more useful: range(n) produces the numbers 0 to n−1, enumerate hands you the position and the value, and zip walks two lists side by side.

A while loop repeats as long as a condition holds — useful when you do not know in advance how many steps you need, like "how many months until the balance reaches 1500?". Its danger is the infinite loop: if nothing inside changes the condition, it never stops. break leaves a loop early, continue skips straight to the next element.

# for: repeat an action for every element of a collection
sales = [120, 80, 300]
for amount in sales:
    print("sale:", amount)

# range(n): the numbers 0, 1, ..., n-1
for day in range(3):
    print("day", day)

# enumerate: position AND value — instead of range(len(...))
for i, amount in enumerate(sales, start=1):
    print(f"order #{i}: {amount}")

# zip: walk two lists side by side
users = ["ann", "bob", "eve"]
for user, amount in zip(users, sales):
    print(user, amount)

# while: repeat WHILE a condition holds — you must make it stop
balance, months = 1000.0, 0
while balance < 1500:
    balance *= 1.05              # +5% per month
    months += 1
print("months to reach 1500:", months)

# break stops the loop early; continue skips to the next element
for amount in [120, -5, 300, 9999, 40]:
    if amount < 0:
        continue                 # skip invalid values
    if amount > 5000:
        print("suspicious amount, stopping")
        break
    print("ok:", amount)
# output when run (verified):sale: 120 sale: 80 sale: 300 day 0 day 1 day 2 order #1: 120 order #2: 80 order #3: 300 ann 120 bob 80 eve 300 months to reach 1500: 9 ok: 120 ok: 300 suspicious amount, stopping
Two habits worth building early: use for when you know what you are iterating over and keep while for "until something happens". And never write for i in range(len(items)) just to get an index — enumerate gives you both, and reads as plain English.

1.5 · Comprehensions: a loop in one line

A comprehension builds a collection in one line. The gain is not brevity but intent: it says "this is a transformation of that", instead of "make an empty list, then append over and over".

orders = [
    {"id": 1, "amount": 120, "status": "paid"},
    {"id": 2, "amount": 0,   "status": "cancelled"},
    {"id": 3, "amount": 340, "status": "paid"},
]

amounts  = [o["amount"] for o in orders]                        # transform
paid     = [o["amount"] for o in orders if o["status"] == "paid"]  # + filter
by_id    = {o["id"]: o["amount"] for o in orders}               # dict
statuses = {o["status"] for o in orders}                        # set

print(amounts)
print(paid)
print(by_id)
print(sorted(statuses))
# output when run (verified):[120, 0, 340] [120, 340] {1: 120, 2: 0, 3: 340} ['cancelled', 'paid']
1.6 · Functions: why they exist

A function is how you stop copy-pasting. The real benefit is not elegance: when a formula changes you fix it once instead of hunting every copy — and a copy you miss is exactly how two slides end up disagreeing.

Anatomy of a function

Every function has the same parts. Once you can name them, any function you read stops looking like a wall of symbols.

def conversion(visitors, buyers, digits=2):
    """Share of visitors who bought, in %."""
    if visitors == 0:
        return None
    return round(buyers / visitors * 100, digits)

print(conversion(900, 45))   # 5.0
  1. 1deftells Python "a function starts here"
  2. 2conversionthe name — a verb or a noun that says what it returns
  3. 3visitors, buyersparameters — the inputs, named placeholders
  4. 4digits=2a default value — this argument becomes optional
  5. 5"""…"""the docstring — shown as a hint in your editor
  6. 6if visitors == 0a guard — handles the impossible case first
  7. 7returnsends the result back and ends the function
  8. 8conversion(900, 45)the call — real values (arguments) fill the parameters
Parameter or argument? They are often mixed up at interviews. A parameter is the name in the definition (visitors); an argument is the actual value passed in the call (900).
def lift(control, variant):
    """Relative uplift in %. The docstring is what your editor
    shows as a hint later — it is not decoration."""
    if control == 0:
        return None                 # honestly return "unknown"
    return (variant - control) / control * 100

print(round(lift(0.098, 0.1136), 1))
print(lift(0, 0.05))                # None — no division by zero

def summarize(values, digits=2, with_median=True):
    out = {"n": len(values), "mean": round(sum(values)/len(values), digits)}
    if with_median:
        srt = sorted(values); mid = len(srt)//2
        out["median"] = round(srt[mid] if len(srt) % 2 else (srt[mid-1]+srt[mid])/2, digits)
    return out

print(summarize([120, 80, 340, 55]))
# output when run (verified):15.9 None {'n': 4, 'mean': 148.75, 'median': 100.0}
Rule of thumb: a calculation that appears twice is a function waiting to happen. Add a docstring — that is the text your editor shows as a hint later.
1.7 · Functions in depth: arguments, scope and traps

Arguments. You can pass arguments by position or by name. Named (keyword) arguments make a call self-explanatory — conversion(visitors=900, conversions=45) cannot be misread — and a default value makes an argument optional.

The classic trap. A default value is created once, when the function is defined — not on every call. If that default is a list, every call shares the same list, and data from one call leaks into the next. The fix is a convention everyone uses: default to None and create the list inside.

Scope. A variable created inside a function lives only inside it and disappears when the function returns. Assigning to a name inside a function creates a new local variable — it does not touch a global one with the same name. That isolation is a feature: functions cannot quietly break each other.

Functions as values. In Python a function is an object you can pass around. sorted, max and min accept a key — a function that says what to compare. A lambda is a short unnamed function written right there, ideal for exactly this.

# 1. Positional vs keyword arguments, defaults
def conversion(conversions, visitors, as_percent=True, digits=1):
    rate = conversions / visitors
    return round(rate * 100, digits) if as_percent else rate

print(conversion(45, 900))                         # positional
print(conversion(visitors=900, conversions=45))    # keywords: order no longer matters
print(conversion(45, 900, as_percent=False))

# 2. THE TRAP: a mutable default is created ONCE and shared by every call
def add_event_bad(event, log=[]):
    log.append(event)
    return log

print(add_event_bad("open"))
print(add_event_bad("click"))     # surprise: "open" is still there!

def add_event_good(event, log=None):
    if log is None:               # a fresh list on every call
        log = []
    log.append(event)
    return log

print(add_event_good("open"))
print(add_event_good("click"))

# 3. Returning several values = returning a tuple, then unpacking it
def min_max_mean(values):
    return min(values), max(values), sum(values) / len(values)

lo, hi, avg = min_max_mean([120, 80, 340, 55])
print(lo, hi, avg)

# 4. *args collects extra positional args, **kwargs extra keyword args
def log_metric(name, *values, **tags):
    print(name, values, tags)

log_metric("dau", 120, 135, 128, platform="ios", country="RU")

# 5. Scope: a variable created inside a function lives only there
total = 0
def add(x):
    total = x          # a NEW local variable, the global one is untouched
    return total
add(5)
print("global total is still", total)

# 6. lambda: a tiny unnamed function, most often used as a sort key
orders = [("ann", 300), ("bob", 120), ("eve", 540)]
print(sorted(orders, key=lambda o: o[1], reverse=True))
print(max(orders, key=lambda o: o[1]))
# output when run (verified):5.0 5.0 0.05 ['open'] ['open', 'click'] ['open'] ['click'] 55 340 148.75 dau (120, 135, 128) {'platform': 'ios', 'country': 'RU'} global total is still 0 [('eve', 540), ('ann', 300), ('bob', 120)] ('eve', 540)
Look at the output: the second call to add_event_bad returned ['open', 'click'] although we only passed "click". That is the mutable-default bug in action — and one of the most common Python interview questions.
1.8 · Strings and f-strings

Strings are everywhere in analytics: messy CSV columns, event names, log lines — and a whole family of interview problems. Four methods cover most needs: split cuts a string into a list, join glues a list back, strip removes surrounding spaces, replace swaps one fragment for another.

An f-string puts values straight into text, and the part after the colon controls formatting: :.1% shows a share as a percentage, :,.0f adds thousands separators, :>6 right-aligns in six characters. One more thing to remember: strings are immutable — every method returns a new string and leaves the original untouched.

# Strings are everywhere: messy CSV columns, logs, interview questions
raw = "  Ivan PETROV ;ivan@mail.ru; Moscow  "

name, email, city = [part.strip() for part in raw.split(";")]
print(name.title(), "|", email.lower(), "|", city)

print(", ".join(["RU", "KZ", "BY"]))          # list -> one string
print("checkout_page_v2".replace("_", " "))
print("2026-03-15".startswith("2026"))

# f-strings: the cleanest way to format numbers for a report
conv, revenue, users = 0.04837, 1234567.891, 42
print(f"conversion: {conv:.1%}")             # percent, 1 decimal
print(f"revenue:    {revenue:,.0f}")         # thousands separator
print(f"users:      {users:>6}")             # right-align in 6 chars
print(f"{'metric':<10}|{'value':>8}")         # simple aligned table

# Strings are immutable: methods return a NEW string
s = "hello"
s.upper()
print(s)             # still "hello"
s = s.upper()
print(s)
# output when run (verified):Ivan Petrov | ivan@mail.ru | Moscow RU, KZ, BY checkout page v2 True conversion: 4.8% revenue: 1,234,568 users: 42 metric | value hello HELLO
The immutability trap: writing s.upper() on its own line does nothing visible — the result is thrown away. You must assign it: s = s.upper(). The output above shows both.
1.9 · Errors and exceptions

Real data is broken. When Python hits something it cannot do — turn "n/a" into a number, divide by zero — it raises an exception and stops. try / except lets you catch it and decide what to do instead: skip the value, log it, use a default.

Two more pieces: else runs only if no error happened, and finally runs no matter what. And sometimes the right move is the opposite — raise your own error with a clear message, so a nonsensical input fails loudly instead of producing a quietly wrong number.

# A real export: some values are broken. The script must not die on them.
raw_amounts = ["120.5", "80", "n/a", "", "340,2", "55"]

parsed, failed = [], []
for raw in raw_amounts:
    try:
        value = float(raw.replace(",", "."))   # may raise ValueError
    except ValueError:
        failed.append(raw)                      # catch ONLY what we expect
    else:
        parsed.append(value)                    # runs only if no error

print("parsed:", parsed)
print("failed:", failed)

# raise: stop with a clear message when an input makes no sense
def safe_rate(part, whole):
    if whole <= 0:
        raise ValueError(f"whole must be positive, got {whole}")
    return part / whole

try:
    safe_rate(5, 0)
except ValueError as e:
    print("caught:", e)

# finally runs no matter what — use it to clean up
try:
    result = 10 / 2
finally:
    print("done, result =", result)
# output when run (verified):parsed: [120.5, 80.0, 340.2, 55.0] failed: ['n/a', ''] caught: whole must be positive, got 0 done, result = 5.0
Never write a bare except:. It also swallows typos in variable names and even Ctrl+C, hiding real bugs. Catch the specific error you expect — here ValueError — and let everything else surface.

2.1 · Complexity in one paragraph

Complexity answers one question: as data grows, how fast does the work grow? O(n) means one pass — double the rows, double the time. O(n²) means comparing every element with every other — double the rows and the time goes up fourfold. Most "why is my script hanging" stories are an accidental O(n²).

The practical takeaway: a loop inside a loop over the same data is a red flag. Almost always it can be replaced by a dictionary lookup, turning O(n²) into O(n).

import time

def has_duplicate_slow(items):      # O(n^2) — every pair compared
    for i in range(len(items)):
        for j in range(i+1, len(items)):
            if items[i] == items[j]:
                return True
    return False

def has_duplicate_fast(items):      # O(n) — one pass, remembering
    seen = set()
    for x in items:
        if x in seen:
            return True
        seen.add(x)
    return False

data = list(range(5000))            # worst case: no duplicates at all

t0 = time.perf_counter(); has_duplicate_slow(data); slow = time.perf_counter()-t0
t0 = time.perf_counter(); has_duplicate_fast(data); fast = time.perf_counter()-t0
print(f"O(n^2): {slow*1000:.1f} ms")
print(f"O(n):   {fast*1000:.2f} ms")
print(f"faster: {slow/fast:.0f}x")
# output when run (verified):O(n^2): 288.8 ms O(n): 0.51 ms faster: 566x
2.2 · Pattern: a dict as memory

The single most useful pattern in analytics. Instead of comparing every pair, you walk once and remember what you have already seen. Whenever a task sounds like "find a pair / find a duplicate / match one table to another", this is the shape of the answer.

# Pattern: a dict remembers what we have already seen.
# Analytical meaning: find two orders that add up to a target sum.
def two_sum(nums, target):
    seen = {}                       # value -> index
    for i, n in enumerate(nums):
        if target - n in seen:      # has the complement appeared before?
            return [seen[target - n], i]
        seen[n] = i
    return []

print(two_sum([120, 45, 300, 80, 55], 135))   # 80 + 55

# Same pattern: match two tables by key without a nested loop
users  = {101: "RU", 102: "KZ", 103: "RU"}
orders = [(101, 120), (103, 340), (999, 50)]
joined = [(uid, amt, users.get(uid, "unknown")) for uid, amt in orders]
print(joined)
# output when run (verified):[3, 4] [(101, 120, 'RU'), (103, 340, 'RU'), (999, 50, 'unknown')]
Why this matters beyond interviews: a merge in pandas is exactly this — it builds a hash of one table and walks the other once. Understanding the pattern is understanding why a join on an indexed key is fast.
2.3 · Pattern: counting and top-K

Counting occurrences is the most common analytical operation there is: popular pages, frequent errors, best-selling items. Counter does it in one pass and hands you the ranking ready-made.

from collections import Counter

pages = ["/home","/pricing","/home","/docs","/home","/pricing","/blog"]

counts = Counter(pages)
print(counts)                       # how many times each page appeared
print(counts.most_common(2))        # ranking, ready-made

# Share of traffic, not just raw counts
total = sum(counts.values())
for page, n in counts.most_common(3):
    print(f"{page:<10} {n}  {n/total*100:.0f}%")
# output when run (verified):Counter({'/home': 3, '/pricing': 2, '/docs': 1, '/blog': 1}) [('/home', 3), ('/pricing', 2)] /home 3 43% /pricing 2 29% /docs 1 14%
2.4 · Pattern: sliding window

When a question involves "k consecutive days", recomputing the sum for every position is wasteful. A sliding window adds the entering value and subtracts the leaving one — one pass instead of many. This is precisely what rolling() does in pandas.

# Best 3 consecutive days of sales.
# Naive: recompute the sum for every position — O(n*k)
# Sliding window: add the entering value, subtract the leaving one — O(n)
def max_window(values, k):
    current = sum(values[:k])
    best = current
    for i in range(k, len(values)):
        current += values[i] - values[i - k]
        best = max(best, current)
    return best

sales = [120, 80, 300, 55, 400, 90, 20]
print(max_window(sales, 3))         # 300 + 55 + 400

# pandas does exactly this with rolling()
import pandas as pd
print(pd.Series(sales).rolling(3).sum().max())
# output when run (verified):755 755.0
2.5 · Pattern: grouping by a computed key

Sometimes the key you need is not in the data — you compute it. Sorting the letters of a word groups anagrams; normalising a name groups duplicate customers; rounding a timestamp groups events into hours. The mechanism is identical, and it is what groupby does under the hood.

from collections import defaultdict

# Pattern: group by a key you compute yourself.
def group_by_key(items, key_fn):
    groups = defaultdict(list)
    for x in items:
        groups[key_fn(x)].append(x)
    return dict(groups)

# Anagrams: the key is the sorted letters
words = ["listen", "silent", "enlist", "google", "gogole"]
print(group_by_key(words, lambda w: "".join(sorted(w))))

# Same mechanism, real task: merge duplicate customers
names = ["Ivan Petrov", "ivan  petrov", "Anna Sidorova"]
normalise = lambda s: " ".join(s.lower().split())
print(group_by_key(names, normalise))
# output when run (verified):{'eilnst': ['listen', 'silent', 'enlist'], 'eggloo': ['google', 'gogole']} {'ivan petrov': ['Ivan Petrov', 'ivan petrov'], 'anna sidorova': ['Anna Sidorova']}
What ties these together: four of the five problems above are solved by "remember what you have seen in a dict or set". That single idea converts brute-force comparison into a single pass — and it is the foundation of every fast operation in pandas.
3 · Working with data

Where the language stops and the craft begins. Half of all analytical errors are born not in the calculation but in how the table was assembled.

3.1 · numpy: why vectorisation

numpy stores numbers in one continuous block of memory and applies an operation to the whole block at once, in compiled code. A Python loop, by contrast, unpacks and repacks every value individually. That is where the order-of-magnitude difference comes from — it is not a style preference.

import numpy as np, pandas as pd, time

s = pd.Series(np.random.rand(100_000))

t0 = time.perf_counter(); loop = [v * 1.2 for v in s];  t_loop = time.perf_counter()-t0
t0 = time.perf_counter(); vec  = s * 1.2;               t_vec  = time.perf_counter()-t0

print(f"loop:   {t_loop*1000:.1f} ms")
print(f"vector: {t_vec*1000:.1f} ms")
print(f"faster: {t_loop/t_vec:.0f}x")

# numpy also gives whole-array maths in one call
a = np.array([120.0, 80.0, 340.0, 55.0])
print(a.mean(), a.std().round(2), np.percentile(a, 90))
# output when run (verified):loop: 7.9 ms vector: 0.5 ms faster: 15x 148.75 112.83 274.00000000000006
Rule: if you are writing for over the rows of a DataFrame, there is almost certainly a vector equivalent. The exact multiple depends on the machine, but the order of magnitude is stable.
3.2 · Building a dataset properly

The most common mistake is leaving everything as strings. Then dates will not sort, categories waste memory, and numbers will not add up. Declare types as you build the table, not after something breaks.

Note the fixed seed. Anything random — sampling, simulation, synthetic data — must be reproducible, otherwise tomorrow you get different numbers and cannot tell whether the data changed or you simply got lucky.

import pandas as pd, numpy as np

rng = np.random.default_rng(42)      # fixed seed -> reproducible
n = 500

users = pd.DataFrame({
    "user_id": np.arange(1, n+1),                              # int
    "signup":  pd.to_datetime("2026-01-01")                    # real dates
               + pd.to_timedelta(rng.integers(0, 180, n), unit="D"),
    "country": pd.Categorical(rng.choice(["RU","KZ","BY"], n, p=[.6,.25,.15])),
    "plan":    pd.Categorical(rng.choice(["free","pro"], n, p=[.75,.25]),
                              categories=["free","pro"], ordered=True),
    "revenue": np.round(rng.lognormal(2.5, 1.1, n), 2),
})
users.loc[rng.choice(n, 25, replace=False), "revenue"] = np.nan   # realistic gaps

print(users.dtypes.to_string())

obj_kb = users["country"].astype(object).memory_usage(deep=True)/1024
cat_kb = users["country"].memory_usage(deep=True)/1024
print(f"\nobject: {obj_kb:.1f} KB | category: {cat_kb:.1f} KB "
      f"-> {obj_kb/cat_kb:.0f}x smaller")
# output when run (verified):user_id int64 signup datetime64[us] country category plan category revenue float64 object: 25.0 KB | category: 0.8 KB -> 33x smaller
Why category matters: on 500 rows the saving is invisible, on ten million it is the difference between "the table fits in memory" and "the kernel died". It also gives correct sorting: ordered=True knows that free comes before pro.
3.3 · Long and wide format

This is the central idea of data organisation. Wide is comfortable for a human reading a report. Long (or "tidy") is the only shape that group-bys and plotting libraries work with naturally.

import pandas as pd

wide = pd.DataFrame({
    "user_id": [1, 2, 3],
    "jan": [100, 150, 90], "feb": [120, 140, 110], "mar": [130, 160, 95],
})
print("WIDE — easy for a human to read:")
print(wide.to_string(index=False))

# melt: wide -> long. One row = one observation
long = wide.melt(id_vars="user_id", var_name="month", value_name="revenue")
print("\nLONG — easy to analyse:")
print(long.head(4).to_string(index=False))

# pivot: long -> wide again, for a report
print("\nBack via pivot:")
print(long.pivot(index="user_id", columns="month", values="revenue").to_string())
# output when run (verified):WIDE — easy for a human to read: user_id jan feb mar 1 100 120 130 2 150 140 160 3 90 110 95 LONG — easy to analyse: user_id month revenue 1 jan 100 2 jan 150 3 jan 90 1 feb 120 Back via pivot: month feb jan mar user_id 1 120 100 130 2 140 150 160 3 110 90 95
The tidy rule: one row is one observation, one column is one variable. If column names contain values (jan, feb, mar are values of the variable "month"), the table is wide and should be reshaped with melt before analysis.
Spot the detail in the output: after pivot the columns came back alphabetically — feb, jan, mar. For months that is wrong. This is exactly why a month should be stored as a date or an ordered category, never as a plain string.
3.4 · pandas: select, group, join

Four operations cover most day-to-day work: look at the data, select what you need, group it, and join it to another table. Everything else is a variation.

3.5 · Checking and cleaning

This is the step that separates an analyst from someone who can write code. A beautiful chart built on broken data is worse than no chart at all, because people will believe it.

The ritual after every load: shape, missing values, duplicates, types, and value ranges. Five lines that catch most problems before they reach a presentation.
import pandas as pd, numpy as np

df = pd.DataFrame({
    "user_id": [1, 2, 2, 3, 4, 5],
    "signup":  ["2026-01-05","2026-01-07","2026-01-07","2026-02-01",None,"2026-02-14"],
    "revenue": [100.0, np.nan, np.nan, 250.0, 80.0, -15.0],

print("\nfull duplicate rows:", df.duplicated().sum())

print("\ncountries after cleaning:", df["country"].unique().tolist())
print("negative revenue:", (df["revenue"] < 0).sum(), "rows")

3.6 · Writing code you can trust

Analytical code is read more often than it is written, and decisions are made from its output. Badly written code is not merely ugly — it quietly produces wrong numbers.

Names instead of riddles. d, x, tmp2 mean nothing a week later. orders, paid_orders, arpu_by_country read like a sentence. A variable name is free documentation.

An explicit copy instead of a warning. The most common pandas trap: you filter a table, then write into the result, and pandas cannot tell whether you meant to change the copy or the original. The result is a warning and values that silently do not get written.

One readable chain instead of five variables. With t1…t5 it is easy to lose track of which one is current and accidentally carry a stale table into the final calculation.

import pandas as pd

orders = pd.DataFrame({"country": ["RU","KZ","RU"],
                       "amount":  [1200, 300, 800],
                       "status":  ["paid","paid","cancelled"]})

# BAD: pandas cannot tell if you mean the copy or the original
subset = orders[orders["country"] == "RU"]
# subset["is_big"] = subset["amount"] > 1000    -> SettingWithCopyWarning

# GOOD 1: say explicitly that this is a separate table
subset = orders[orders["country"] == "RU"].copy()
subset["is_big"] = subset["amount"] > 1000

# GOOD 2: modify the original through .loc, no intermediate table
orders.loc[orders["country"] == "RU", "is_big"] = orders["amount"] > 1000

# One readable chain instead of five throwaway variables
top = (orders
       .query("status == 'paid' and amount > 0")
       .groupby("country")["amount"]
       .sum()
       .sort_values(ascending=False)
       .head(5))
print(top.to_string())
# output when run (verified):country RU 1200 KZ 300
The underlying point: code is written once and read dozens of times. If you have to decode your own script, that is not saved time — it is a deferred error.

Case 4 · A/B test
Task: "Variant A shows 11.36% against the control's 9.80%. Ship it?"

A point estimate alone means nothing — you need the confidence interval. If the intervals overlap, the difference may well be noise.

import numpy as np, pandas as pd
from scipy import stats
import matplotlib.pyplot as plt
plt.rcParams.update({
    "axes.spines.top": False, "axes.spines.right": False,
    "axes.edgecolor": "#d5d8e6", "axes.labelcolor": "#4a4f66",
    "xtick.color": "#4a4f66", "ytick.color": "#4a4f66",
    "axes.grid": True, "axes.axisbelow": True,
    "grid.color": "#eceef5", "font.size": 10,
})

data = {"Control": (2500, 245), "Variant A": (2500, 284), "Variant B": (2500, 262)}

rows = []
for name, (n, c) in data.items():
    p = c / n
    se = np.sqrt(p * (1 - p) / n)                 # standard error of a proportion
    rows.append({"group": name, "p": p * 100,
                 "lo": (p - 1.96 * se) * 100, "hi": (p + 1.96 * se) * 100})
df = pd.DataFrame(rows)
print(df.round(2).to_string(index=False))

n1, c1 = data["Control"]; n2, c2 = data["Variant A"]
p1, p2 = c1 / n1, c2 / n2
se_diff = np.sqrt(p1 * (1 - p1) / n1 + p2 * (1 - p2) / n2)
z = (p2 - p1) / se_diff
print(f"\nz = {z:.3f}, p-value = {2 * (1 - stats.norm.cdf(abs(z))):.4f}")

fig, ax = plt.subplots(figsize=(7, 3.0))
y = range(len(df))
ax.errorbar(df["p"], y, xerr=[df["p"] - df["lo"], df["hi"] - df["p"]],
            fmt="o", ms=9, lw=2.2, capsize=6, color="#5B5FE9", ecolor="#a59cf7")
ax.axvline(df.loc[0, "p"], color="#9aa0b8", ls="--", lw=1.2)
for yi, r in zip(y, df.itertuples()):
    ax.text(r.hi + 0.12, yi, f"{r.p:.2f}%", va="center", fontweight="bold", color="#1e2233")
ax.set_yticks(list(y)); ax.set_yticklabels(df["group"])
ax.set_xlabel("Conversion, % (bars = 95% CI)")
ax.grid(axis="y", visible=False)
ax.set_title("Intervals overlap the control: no winner yet", loc="left", fontweight="bold")
plt.show()
# output when run (verified): group p lo hi Control 9.80 8.63 10.97 Variant A 11.36 10.12 12.60 Variant B 10.48 9.28 11.68 z = 1.794, p-value = 0.0729
Produced by the code above
Conclusion: p = 0.073 > 0.05 and variant A's interval overlaps the control. The difference is not significant — shipping now would be premature. This is exactly why error bars are more honest than bare bars.
Case 5 · RFM segmentation
Task: "We have 800 customers and one campaign budget. Who do we write to?"

RFM splits the base along three axes: Recency, Frequency, Monetary. Each axis is cut into quintiles with qcut, and the scores combine into segments.

import numpy as np, pandas as pd
import matplotlib.pyplot as plt
plt.rcParams.update({
    "axes.spines.top": False, "axes.spines.right": False,
    "axes.edgecolor": "#d5d8e6", "axes.labelcolor": "#4a4f66",
    "xtick.color": "#4a4f66", "ytick.color": "#4a4f66",
    "axes.grid": True, "axes.axisbelow": True,
    "grid.color": "#eceef5", "font.size": 10,
})

rng = np.random.default_rng(5)
df = pd.DataFrame({
    "recency":   rng.exponential(30, 800).clip(1, 180).round(0),
    "frequency": rng.poisson(4, 800) + 1,
    "monetary":  rng.lognormal(3.2, 1.0, 800).round(2),
})

# qcut splits into equal-sized groups (quintiles).
# Recency is reversed: fewer days since purchase = better = score 5
df["R"] = pd.qcut(df["recency"], 5, labels=[5, 4, 3, 2, 1]).astype(int)
df["F"] = pd.qcut(df["frequency"].rank(method="first"), 5, labels=[1, 2, 3, 4, 5]).astype(int)

def segment(r):
    if r.R >= 4 and r.F >= 4: return "Champions"
    if r.R >= 4 and r.F <= 2: return "New"
    if r.R <= 2 and r.F >= 4: return "At risk"
    if r.R <= 2 and r.F <= 2: return "Dormant"
    return "Middle"

df["segment"] = df.apply(segment, axis=1)
print(df["segment"].value_counts().to_string())

colors = {"Champions": "#059669", "At risk": "#E11D48", "New": "#5B5FE9",
          "Dormant": "#9aa0b8", "Middle": "#c4bcf5"}
fig, ax = plt.subplots(figsize=(7, 3.4))
for name, g in df.groupby("segment"):
    ax.scatter(g["recency"], g["frequency"], s=np.sqrt(g["monetary"]) * 3.2,
               alpha=0.55, color=colors[name], label=name, edgecolors="none")
ax.set_xlabel("Recency — days since last purchase"); ax.set_ylabel("Frequency — purchases")
ax.set_xlim(0, 150)
ax.legend(frameon=False, ncol=3, fontsize=8.5, loc="upper right")
ax.set_title("Dot size = money spent. Red = worth winning back", loc="left", fontweight="bold")
plt.show()
# output when run (verified):segment Middle 287 Champions 150 Dormant 138 New 114 At risk 111
Produced by the code above
Answer for marketing: "At risk" is 111 people who used to buy often and then disappeared. They are the most profitable target for reactivation — they have already proved they will pay. The 138 "dormant" are cheaper to let go.
Case 6 · Finding anomalies
Task: "Something broke in early July but the chart looks normal. Check it."

The technique: smooth the series with a rolling mean, subtract it from the actual values, and flag points where the deviation exceeds a few standard deviations.

import numpy as np, pandas as pd
import matplotlib.pyplot as plt
plt.rcParams.update({
    "axes.spines.top": False, "axes.spines.right": False,

5 · Advanced visualisation

Three techniques that separate an analyst's chart from a spreadsheet default. Each solves a specific perception problem.

Every chart on this page starts with the same short plt.rcParams block: it removes the top and right frame, softens the axes and puts the grid behind the data. Copy it once into your notebook and all your charts lose the "default matplotlib" look.
Small multiples instead of spaghetti

Beyond three series, lines on a single chart become unreadable. The fix is to split into small panels and highlight one segment per panel, keeping the others as grey context.

import numpy as np, pandas as pd
import matplotlib.pyplot as plt

    "axes.spines.top": False, "axes.spines.right": False,
    "axes.edgecolor": "#d5d8e6", "axes.labelcolor": "#4a4f66",
    "xtick.color": "#4a4f66", "ytick.color": "#4a4f66",
    "axes.grid": True, "axes.axisbelow": True,
    "grid.color": "#eceef5", "font.size": 10,
})

rng = np.random.default_rng(21)
segs = ["Mobile iOS", "Mobile Android", "Desktop", "Tablet"]
level = {"Mobile iOS": 62, "Mobile Android": 55, "Desktop": 70, "Tablet": 40}
decay = {"Mobile iOS": 0.9, "Mobile Android": 1.6, "Desktop": 0.5, "Tablet": 2.3}
d = pd.DataFrame([{"segment": s, "week": w,
                   "retention": level[s] - decay[s] * w + rng.normal(0, 1.2)}
                  for s in segs for w in range(12)])

# Weekly drop per segment = slope of a straight-line fit
for s in segs:
    g = d[d.segment == s]
    print(f"{s:<15} {np.polyfit(g.week, g.retention, 1)[0]:+.2f} pp/week")

    for other in segs:                       # grey context: all the others

            ax.plot(g.week, g.retention, color="#dfe2ee", lw=1.2)
    g = d[d.segment == seg]                  # the highlighted segment
    ax.plot(g.week, g.retention, color="#5B5FE9", lw=2.4)
    ax.set_title(seg, loc="left", fontsize=10, fontweight="bold")
fig.supxlabel("Week", color="#4a4f66"); fig.supylabel("Retention, %", color="#4a4f66")

Waterfall: decomposing a change

The question "revenue grew by 73k — where from?" is best answered by a waterfall: every contribution is separate, and gains are distinguished from losses by colour.

import matplotlib.pyplot as plt
plt.rcParams.update({
    "axes.spines.top": False, "axes.spines.right": False,
    "axes.edgecolor": "#d5d8e6", "axes.labelcolor": "#4a4f66",
    "xtick.color": "#4a4f66", "ytick.color": "#4a4f66",
    "axes.grid": True, "axes.axisbelow": True,
    "grid.color": "#eceef5", "font.size": 10,
})

steps  = ["Revenue\nMay", "New\ncustomers", "Win-back", "Upgrades",
          "Downgrades", "Churn", "Revenue\nJune"]
start  = 420
deltas = [85, 22, 48, -19, -63]

fig, ax = plt.subplots(figsize=(7.4, 3.4))
cum, peak = start, start
ax.bar(0, start, color="#5B5FE9", width=0.6)
ax.text(0, start + 10, start, ha="center", fontweight="bold")
for i, v in enumerate(deltas, start=1):
    bottom = cum if v > 0 else cum + v       # the key line of a waterfall
    color = "#059669" if v > 0 else "#E11D48"
    ax.bar(i, abs(v), bottom=bottom, width=0.6, color=color)
    ax.plot([i - 0.7, i - 0.3], [cum, cum], color="#9aa0b8", lw=1, ls=":")
    ax.text(i, bottom + abs(v) + 10, f"{v:+d}", ha="center", fontweight="bold", color=color)
    cum += v
    peak = max(peak, cum)
ax.bar(len(steps) - 1, cum, color="#5B5FE9", width=0.6)
ax.text(len(steps) - 1, cum + 10, cum, ha="center", fontweight="bold")
print("June revenue:", cum)
ax.set_xticks(range(len(steps))); ax.set_xticklabels(steps, fontsize=8.5)
ax.set_ylim(0, peak * 1.15); ax.set_ylabel("Revenue, k")   # room above the PEAK, not the end
ax.grid(axis="x", visible=False)
ax.set_title("Where the growth came from, factor by factor", loc="left", fontweight="bold")
plt.show()
# output when run (verified):June revenue: 493

Implementation subtlety: for negative values the bar's base is cum + v and its height is abs(v). Passing a negative height together with a shifted base draws the bar at half its size — a classic bug when building a waterfall by hand.
Correlation matrix: show half, colour by sign

A full correlation matrix repeats every number twice and wastes the diagonal on 1.00. Mask the upper triangle, trim the empty edge, and use a diverging palette centred on zero — red for positive, blue for negative — so strength and direction read instantly.

import numpy as np, pandas as pd, seaborn as sns
import matplotlib.pyplot as plt
plt.rcParams.update({
    "axes.spines.top": False, "axes.spines.right": False,
    "axes.edgecolor": "#d5d8e6", "axes.labelcolor": "#4a4f66",
    "xtick.color": "#4a4f66", "ytick.color": "#4a4f66",
    "axes.grid": True, "axes.axisbelow": True,
    "grid.color": "#eceef5", "font.size": 10,
})

rng = np.random.default_rng(11)
n = 600
sessions = rng.poisson(8, n) + 1
df = pd.DataFrame({"sessions": sessions})
df["page_views"]   = sessions * rng.normal(4, 0.8, n)
df["time_on_site"] = df["page_views"] * rng.normal(0.9, 0.25, n)
df["orders"]       = rng.poisson(0.12 * sessions)
df["revenue"]      = df["orders"] * rng.lognormal(3.4, 0.5, n)
df["tickets"]      = rng.poisson(0.4, n) + (df["orders"] > 3)

corr = df.corr().round(2)
print(corr["revenue"].sort_values(ascending=False).to_string())

mask = np.triu(np.ones_like(corr, dtype=bool))      # hide the mirrored half
# drop the first row and last column — after masking they are empty
corr_t, mask_t = corr.iloc[1:, :-1], mask[1:, :-1]
fig, ax = plt.subplots(figsize=(6.4, 4.2))
sns.heatmap(corr_t, mask=mask_t, annot=True, fmt=".2f", cmap="RdBu_r", vmin=-1, vmax=1,
            center=0, square=True, linewidths=2, linecolor="white",
            cbar_kws={"shrink": 0.75}, ax=ax)
ax.grid(False)
ax.set_yticklabels(ax.get_yticklabels(), rotation=0)
ax.set_title("Correlation matrix: lower triangle only", loc="left", fontweight="bold")
plt.show()

Dumbbell chart: level and change together

When you compare "before" and "after" across many categories, two bars per category become noise. A dumbbell draws one line per category from the old value to the new one: its position shows the level, its length the size of the change, its colour the direction. Sorting by change puts the story in order.

Calendar heatmap: seasonality you can see

A daily metric as a line hides its weekly rhythm in the wiggle. Fold it into a grid — weekdays as rows, weeks as columns — and the pattern becomes a texture you notice immediately. It is the same idea as the GitHub contribution graph.

import numpy as np, pandas as pd
import matplotlib.pyplot as plt
plt.rcParams.update({
    "axes.spines.top": False, "axes.spines.right": False,
    "axes.edgecolor": "#d5d8e6", "axes.labelcolor": "#4a4f66",
    "xtick.color": "#4a4f66", "ytick.color": "#4a4f66",
    "axes.grid": True, "axes.axisbelow": True,
    "grid.color": "#eceef5", "font.size": 10,
})

rng = np.random.default_rng(4)
days = pd.date_range("2026-01-05", periods=26 * 7)          # 26 full weeks
weekday_effect = np.array([1.00, 1.05, 1.07, 1.04, 0.95, 0.62, 0.58])   # Mon..Sun
dau = (1000 * weekday_effect[days.dayofweek]
       * (1 + 0.004 * np.arange(len(days)))                 # slow growth
       * rng.normal(1, 0.04, len(days)))
s = pd.Series(dau.round(0), index=days)

print(s.groupby(s.index.dayofweek).mean().round(0)
       .rename(index=dict(enumerate(["Mon","Tue","Wed","Thu","Fri","Sat","Sun"]))).to_string())

grid = s.values.reshape(26, 7).T                            # rows = weekdays, cols = weeks
fig, ax = plt.subplots(figsize=(7.6, 2.6))
im = ax.imshow(grid, cmap="Purples", aspect="auto")
ax.set_yticks(range(7)); ax.set_yticklabels(["Mon","Tue","Wed","Thu","Fri","Sat","Sun"])
ax.set_xticks(range(0, 26, 4)); ax.set_xticklabels([f"wk {i+1}" for i in range(0, 26, 4)])
ax.grid(False)
for side in ["left", "bottom"]:
    ax.spines[side].set_visible(False)
fig.colorbar(im, ax=ax, shrink=0.8, label="DAU")
ax.set_title("Calendar heatmap: weekends dip, every single week", loc="left", fontweight="bold")
plt.show()

Rules for a good chart
The title is the conclusion, not the label"Variants overlap the control — no winner" beats "Conversion by group". The reader gets the thought, not the raw data.
Remove the frame and surplus gridlinesAnything that carries no information steals attention from what does.
Label values directly on the chartIt saves the reader from looking back and forth to the axis.
Do not truncate the Y axis on bar chartsBars are compared by length, so a cut axis exaggerates the difference. For lines it is acceptable.
Colour is meaning, not decorationOne accent for the point being made, grey for context. A rainbow without meaning slows reading down.
Show uncertaintyConfidence intervals are more honest than point estimates and prevent premature conclusions.
The test before you send it: cover the title and show the chart to a colleague. If they cannot tell you what point you were making, the chart is not finished.
